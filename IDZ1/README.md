# IDZ1 — модель дуэли двух государств

Индивидуальное задание №1 по курсу «Архитектура компьютеров и операционные системы».

**Вариант:** 7 «Два условных государства»
**Исполнитель:** Андрюшко Георгий Павлович
**Группа:** БПИ253
**Год:** 2026
**Язык:** C (стандарт C11)
**Платформа:** Linux (POSIX)
**Сборка:** CMake + Ninja

## Суть задачи

Два государства на прямоугольных клеточных территориях обмениваются
миномётными выстрелами. На каждой территории размещены цели разной
стоимости. Стороны не знают координат целей противника и выбирают
точку удара случайно либо по заданной стратегии.

Бой для стороны прекращается, когда:

- уничтожены все её цели, либо
- у противника не осталось живых целей, либо
- исчерпаны снаряды (обычные и тяжёлые), либо
- исчерпан экономический лимит (стоимость израсходованных боеприпасов).

## Возможности

- Однопоточная имитация параллелизма: координатор в цикле вызывает
  ходы обеих сторон, «асинхронность» — через псевдослучайные задержки.
- Три стратегии выбора координат: `random`, `center`, `sector`.
- Точность стрельбы (0–100%), настраиваемая для каждой стороны.
- Тяжёлый (площадной) удар: квадрат `(2R+1)×(2R+1)` вокруг точки удара.
- Пополнение боезапаса с заданной интенсивностью.
- Экономический лимит: сторона прекращает огонь при превышении бюджета.
- Три способа запуска: параметры по умолчанию, файл-конфиг,
  расширенный интерактивный ввод.
- Два принципиально разных варианта завершения: естественное
  и по прерыванию (SIGINT/SIGTERM).
- ANSI-цвета в терминале с автоотключением при перенаправлении вывода.
- Лог-файл с полным ходом боя и итоговой статистикой (без ANSI-мусора).
- Ввод-вывод через файловые дескрипторы (`open`/`read`/`write`/`close`).
- Обработка сигналов `SIGINT` и `SIGTERM`.
- Тестовые наборы данных и скрипт автотестов.
- Итоговый вердикт: кто победил или у кого меньше потери в стоимости.

## Сборка

Требования: `gcc`, `cmake`, `ninja`, `gdb` (для отладки).

```bash
sudo apt install build-essential cmake ninja-build gdb

cd IDZ1
mkdir -p build && cd build
cmake .. -G Ninja
ninja
```

Бинарник появится в `build/IDZ1`.

## Запуск

### 1. Параметры по умолчанию

```bash
./build/IDZ1
```

Территория 8×8, по 2 цели у каждой стороны, по 30 снарядов,
точность 70%, бюджет 100.

### 2. Загрузка из файла-конфига

```bash
./build/IDZ1 scripts/cases/case1.conf
./build/IDZ1 scripts/cases/case2.conf    # бесконечный режим
./build/IDZ1 scripts/cases/case3_area.conf
```

### 3. Интерактивный ввод

```bash
./build/IDZ1 --interactive
```

Программа последовательно запрашивает:

- максимум тактов и паузу между тактами;
- точность каждой стороны;
- размеры территорий (число строк и столбцов);
- список целей каждой стороны — по одной в строке в формате
  `строка столбец стоимость`. Пустая строка завершает ввод;
  если сразу нажать Enter, текущие цели сохраняются, если ввести
  хотя бы одну — прежний набор заменяется новым.

Все вводимые значения **валидируются**: проверяются диапазоны,
формат строки, границы поля и занятость клетки. При ошибке значение
отклоняется с сообщением, программа продолжает запрос. Работа
прерывается корректно по `Ctrl+C`.

### 4. Справка

```bash
./build/IDZ1 --help
```

## Формат конфигурационного файла

Простой формат `key = value`, по одному параметру в строке.
Комментарии начинаются с `#`. Пустые строки игнорируются.

### Глобальные параметры

| Параметр    | Описание                                | Пример          |
|-------------|-----------------------------------------|-----------------|
| `max_ticks` | Максимум тактов. `0` = без ограничения  | `max_ticks=200` |
| `tick_ms`   | Базовая задержка между тактами, мс      | `tick_ms=100`   |
| `seed`      | Seed генератора случайных чисел         | `seed=42`       |
| `log`       | Имя лог-файла                           | `log=duel.log`  |

### Параметры стороны (`A.` или `B.`)

| Параметр                 | Описание                                        |
|--------------------------|-------------------------------------------------|
| `name`                   | Название государства                            |
| `rows`, `cols`           | Размеры территории                              |
| `ammo`                   | Стартовое число обычных снарядов                |
| `ammo_cost`              | Стоимость одного обычного выстрела              |
| `budget`                 | Экономический лимит (0 = без лимита)            |
| `accuracy`               | Точность стрельбы, 0–100                        |
| `strategy`               | Стратегия: `random`, `center`, `sector`         |
| `replenish_every`        | Каждые N тактов пополнять боезапас              |
| `replenish_amount`       | На сколько снарядов за раз                      |
| `reaction_ms`            | Базовая задержка реакции, мс                    |
| `reaction_jitter_ms`     | Случайная добавка к задержке, мс                |
| `area_ammo`              | Число тяжёлых снарядов                          |
| `area_cost`              | Стоимость одного тяжёлого залпа                 |
| `area_radius`            | Радиус поражения залпа (квадрат `(2R+1)²`)      |
| `area_every`             | Каждые N тактов применять залп (0 = не применять) |
| `target`                 | Разместить цель: `строка столбец стоимость`     |

Параметры `rows` и `cols` должны идти **до** `target` — иначе сетка
уже будет создана, и размер изменить нельзя.

## Завершение программы

Программа корректно завершается **двумя принципиально разными
способами** — в зависимости от данных она может закончиться сама
или выполняться бесконечно и быть прервана.

**А. Естественное завершение** — программа останавливается сама:

1. **Обе стороны прекратили огонь** — по одному из условий варианта.
2. **Достигнут `max_ticks`** — если задан ненулевой лимит.
3. **Никто не может продолжать огонь** — защита от зацикливания.

**Б. По прерыванию** — получен сигнал `SIGINT` (Ctrl+C) или `SIGTERM`.
Работает в том числе в бесконечном режиме (`max_ticks=0`), когда
естественное завершение невозможно.

Во всех случаях: итоги боя, статистика обеих сторон, финальное
состояние территорий, **вердикт**, закрытие лог-файла.

## Стратегии выбора координат

| Стратегия  | Описание                                             |
|------------|------------------------------------------------------|
| `random`   | Равномерный случайный выбор координат                |
| `center`   | Приближённое смещение к центру (треугольное)         |
| `sector`   | Последовательный обход всех клеток по кругу          |

Стратегия **не использует** информацию о расположении целей —
противник их не знает.

## Тяжёлый удар (площадной)

Раз в `area_every` тактов (если `area_every > 0`, есть тяжёлые снаряды
и бюджет позволяет) сторона тратит один тяжёлый снаряд и накрывает
квадрат `(2R+1)×(2R+1)` вокруг выбранной точки. Все живые цели в этой
области уничтожаются одновременно. Каждая цель при этом учитывается
**один раз**.

Если `area_every=0`, тяжёлые залпы не применяются, и такие снаряды
не считаются боеспособным запасом.

## Лог-файл

Имя лог-файла задаётся параметром `log` в конфиге или по умолчанию
`duel.log`. В лог попадают:

- все события выстрелов и залпов;
- попадания, промахи, уничтожение целей;
- пополнение боезапаса;
- срабатывания условий прекращения огня;
- итоговая статистика обеих сторон;
- вердикт;
- финальное состояние обеих территорий.

Цветовые ANSI-последовательности **вырезаются** при записи в файл —
лог остаётся чистым текстом.

## Автотесты

```bash
./scripts/run_tests.sh
```

Скрипт запускает бинарник на всех конфигах из `scripts/cases/`,
плюс проверяет обработку `SIGINT` и `SIGTERM`. Результаты сохраняются
в `tests/`.

Ожидаемый результат: `===== Итого: 15 / 15 успешно =====`.

## Инварианты

Программа гарантирует:

- **Один выстрел — не более одного снаряда.**
- **Цель учитывается уничтоженной только один раз.**
- **Стоимость и число целей не становятся отрицательными.**
  Стоимости (`initial_cost`, `alive_cost`, `lost_cost`) хранятся в
  `int64_t` — переполнение невозможно.
- **Сторона меняет только территорию противника.**
- **После срабатывания условия завершения сторона не стреляет.**

## Архитектура (модули)

| Модуль       | Роль                                              |
|--------------|---------------------------------------------------|
| `main`       | Координатор: разбор аргументов, главный цикл     |
| `artillery`  | Огневое подразделение                            |
| `side`       | Государство: территория + подразделение          |
| `grid`       | Территория: клетки, цели                         |
| `config`     | Парсер параметров, дефолты, интерактив           |
| `log`        | Логирование через `write()`, вырезание ANSI      |
| `io`         | Построчное чтение через `read()`                 |
| `signals`    | Обработчики SIGINT/SIGTERM                       |
| `colors`     | ANSI-цвета с автоотключением                     |

## Использованные системные вызовы

- `write` — вывод в консоль и лог
- `read` — чтение из файла и stdin
- `open`, `close` — работа с дескрипторами
- `nanosleep` — задержки
- `sigaction` — обработчики сигналов
- `isatty` — определение терминала
