# IDZ2 — модель дуэли двух государств

Индивидуальное задание №2 по курсу «Архитектура компьютеров и операционные системы».

**Вариант:** 7 «Два условных государства»
**Исполнитель:** Андрюшко Георгий Павлович
**Группа:** БПИ253
**Год:** 2026
**Язык:** C (стандарт C11)
**Платформа:** Linux (POSIX)
**Сборка:** CMake + Ninja

## Суть задачи

Два государства на прямоугольных клеточных территориях обмениваются
миномётными выстрелами. На каждой территории размещены цели разной
стоимости. Стороны не знают координат целей противника и выбирают
точку удара случайно либо по заданной стратегии.

Бой для стороны прекращается, когда:

- уничтожены все её цели, либо
- у противника не осталось живых целей, либо
- исчерпаны снаряды (обычные и тяжёлые), либо
- исчерпан экономический лимит (стоимость израсходованных боеприпасов).

## Возможности

- Настоящая многопоточная модель POSIX: два потока сторон, два независимых
  потока огневых подразделений и основной поток-координатор.
- Согласование состояния через `pthread_mutex_t` и POSIX-семафоры:
  событие, начало такта и подтверждение обработки такта.
- Независимые задержки стрельбы; отдельное состояние ГПСЧ каждой стороны
  (xorshift32 с перемешиванием seed и приведением диапазона по старшим битам).
- Два режима времени: реальное время (`tick_ms > 0`) и быстрое моделирование
  (`tick_ms = 0`, детерминированное число выстрелов, см. «Режимы времени»).
- Цели различного **типа** и стоимости (`A.target = строка столбец стоимость [тип]`).
- Три стратегии выбора координат: `random`, `center`, `sector`.
- Точность стрельбы (0–100%), настраиваемая для каждой стороны.
- Тяжёлый (площадной) удар: квадрат `(2R+1)×(2R+1)` вокруг точки удара.
- Пополнение боезапаса с заданной интенсивностью.
- Экономический лимит: следующий выстрел не выполняется, если его стоимость превысит оставшийся бюджет; выстрел, после которого расходы ровно равны бюджету, допустим.
- Три способа запуска: параметры по умолчанию, файл-конфиг,
  интерактивный ввод (включая боезапас, бюджет, стратегию, пополнение,
  тяжёлые снаряды и seed).
- Завершение: обе стороны прекратили огонь, достигнут лимит тактов
  либо прерывание пользователем (SIGINT/SIGTERM).
- ANSI-цвета в терминале с автоотключением при перенаправлении вывода.
- Лог-файл с полным ходом боя и итоговой статистикой (без ANSI-мусора).
- Ввод конфигурации и основной игровой вывод/логирование используют POSIX-файловые дескрипторы (`open`/`read`/`write`/`close`). Несколько диагностических сообщений командной строки в `main.c` выводятся через `fprintf(stderr, ...)` — поэтому утверждение, что абсолютно весь ввод-вывод использует только дескрипторы, было бы неточным.
- Обработка сигналов `SIGINT` и `SIGTERM`; `SIGPIPE` игнорируется, поэтому
  `./build/IDZ2 ... | head` не обрывает лог-файл.
- Тестовые наборы данных и скрипт автотестов.
- Итоговый вердикт: кто победил или у кого меньше потери в стоимости.

## Модель потоков и синхронизация

Приложение содержит пять участников выполнения:

| Участник | Ответственность |
|---|---|
| Поток стороны A | Проверка условий прекращения огня и пополнение запасов A на каждом такте |
| Поток стороны B | Аналогичное обслуживание стороны B |
| Огневой поток A | Асинхронный выбор координат и выстрелы по территории B |
| Огневой поток B | Асинхронный выбор координат и выстрелы по территории A |
| Главный поток | Координатор тактов, глобальное завершение и обработка сигналов |

Общая игровая структура защищена мьютексом. Проверка условий завершения
стороны, выстрел, расход снаряда, изменение клетки и статистики выполняются
под одной блокировкой, поэтому завершившая сторона не успевает выстрелить ещё раз.
Каждая сторона проверяет и меняет только свой флаг `active`; флаги после выстрела
по противнику обновляет сам противник перед своим выстрелом либо координатор.
Семафоры `tick_sem[]` сообщают потокам сторон о новом такте, `tick_ack[]` подтверждают
его обработку, `event_sem` будит координатор при появлении события, а в быстром
режиме `fire_sem[]`/`fire_ack[]` разрешают огневому потоку выстрел такта и
подтверждают, что такт им отработан. Вывод в консоль и лог дополнительно
защищён мьютексом логгера. SIGINT/SIGTERM обрабатывает координатор; рабочие
потоки блокируют эти сигналы, чтобы прерывание не осталось необработанным
в потоке, который спит.

## Сборка

Требования: `gcc`, `cmake` (и `ninja` либо `make`), POSIX Threads (`pthread`).

```bash
sudo apt install build-essential cmake ninja-build

cd IDZ2
mkdir -p build && cd build
cmake .. -G Ninja && ninja      # либо: cmake .. && make
```

Без CMake: `mkdir -p build && gcc -std=c11 -Wall -Wextra -Iinclude src/*.c -o build/IDZ2 -lpthread`.

Бинарник появится в `build/IDZ2`.

## Запуск

### 1. Параметры по умолчанию

```bash
./build/IDZ2
```

Территория 8×8, по 2 цели у каждой стороны, по 30 снарядов,
точность 70%, бюджет 100.

### 2. Загрузка из файла-конфига

```bash
./build/IDZ2 scripts/cases/case1.conf
./build/IDZ2 scripts/cases/case2.conf    # бесконечный режим
./build/IDZ2 scripts/cases/case3_area.conf
```

### 3. Интерактивный ввод

```bash
./build/IDZ2 --interactive
```

Программа последовательно запрашивает:

- максимум тактов и паузу между тактами (`0` — быстрый режим);
- точность каждой стороны;
- задержку реакции и её разброс для каждой стороны;
- размеры территорий (число строк и столбцов);
- список целей каждой стороны — по одной в строке в формате
  `строка столбец стоимость [тип]`. Пустая строка завершает ввод;
  если сразу нажать Enter, текущие цели сохраняются, если ввести
  хотя бы одну — прежний набор заменяется новым;
- «Изменить расширенные параметры?» — при ответе `д`: seed и для каждой стороны
  число и цена обычных снарядов, бюджет, стратегия, пополнение, тяжёлые снаряды
  (радиус, цена, период). Enter оставляет текущее значение.

Все вводимые значения **валидируются**: проверяются диапазоны,
формат строки, границы поля и занятость клетки. При ошибке значение
отклоняется с сообщением, программа продолжает запрос. Работа
прерывается корректно по `Ctrl+C` (код возврата 0). Если входной поток
закончился до завершения ввода, программа сообщает об этом и возвращает код 1.

### 4. Справка

```bash
./build/IDZ2 --help
```

## Формат конфигурационного файла

Простой формат `key = value`, по одному параметру в строке.
Комментарии начинаются с `#`. Пустые строки игнорируются.

### Глобальные параметры

| Параметр    | Описание                                | Пример          |
|-------------|-----------------------------------------|-----------------|
| `max_ticks` | Максимум тактов. `0` = без ограничения  | `max_ticks=200` |
| `tick_ms`   | Базовая задержка между тактами, мс      | `tick_ms=100`   |
| `seed`      | Seed генератора случайных чисел         | `seed=42`       |
| `log`       | Имя лог-файла                           | `log=duel.log`  |

### Параметры стороны (`A.` или `B.`)

| Параметр                 | Описание                                        |
|--------------------------|-------------------------------------------------|
| `name`                   | Название государства                            |
| `rows`, `cols`           | Размеры территории                              |
| `ammo`                   | Стартовое число обычных снарядов                |
| `ammo_cost`              | Стоимость одного обычного выстрела              |
| `budget`                 | Экономический лимит (0 = без лимита)            |
| `accuracy`               | Точность стрельбы, 0–100                        |
| `strategy`               | Стратегия: `random`, `center`, `sector`         |
| `replenish_every`        | Каждые N тактов пополнять боезапас              |
| `replenish_amount`       | На сколько снарядов за раз                      |
| `reaction_ms`            | Базовая задержка реакции, мс                    |
| `reaction_jitter_ms`     | Случайная добавка к задержке, мс                |
| `area_ammo`              | Число тяжёлых снарядов                          |
| `area_cost`              | Стоимость одного тяжёлого залпа                 |
| `area_radius`            | Радиус поражения залпа (квадрат `(2R+1)²`)      |
| `area_every`             | Каждые N тактов применять залп (0 = не применять) |
| `target`                 | Разместить цель: `строка столбец стоимость [тип]` |

Параметры `rows` и `cols` должны идти **до** `target` — иначе сетка
уже будет создана, и размер изменить нельзя.

Стоимость цели — от 0 до 1 000 000 000, тип — одно слово (до 16 разных типов на
территорию; без указания тип «цель»). Недопустимая цель отклоняется с сообщением,
запуск прекращается с кодом 1.

**Значения по умолчанию.** Параметры, не указанные в файле, не обнуляются, а берутся
из значений по умолчанию (например, бюджет 100, 2 тяжёлых снаряда каждые 10 тактов).
Если сценарию они не нужны, их надо задать явно (`budget=0`, `area_ammo=0`).
Радиус `0` допустим (залп накрывает только клетку прицеливания), цена тяжёлого
снаряда `0` допустима (бесплатный снаряд).

## Завершение программы

Программа корректно завершается **двумя принципиально разными
способами** — в зависимости от данных она может закончиться сама
или выполняться бесконечно и быть прервана.

**А. Естественное завершение** — программа останавливается сама:

1. **Обе стороны прекратили огонь** — по одному из условий варианта
   (свои цели уничтожены, у противника целей нет, закончился боеспособный запас без возможности пополнения, либо следующий выстрел превысил бы бюджет).
   Завершение стороны окончательно: после сообщения «ПРЕКРАЩАЕТ ОГОНЬ» она больше
   не стреляет. Сторона с пустым запасом, но настроенным пополнением, ждёт
   пополнения и огонь не прекращает (если бюджет позволяет выстрел после него).
2. **Достигнут `max_ticks`** — если задан ненулевой лимит.

**Б. По прерыванию** — получен сигнал `SIGINT` (Ctrl+C) или `SIGTERM`.
Работает в том числе в бесконечном режиме (`max_ticks=0`), когда
естественное завершение невозможно.

Во всех случаях: итоги боя, статистика обеих сторон, финальное
состояние территорий, **вердикт**, закрытие лог-файла.

## Режимы времени

| `tick_ms` | Поведение |
|---|---|
| `> 0` | Такт длится `tick_ms` мс реального времени. Огневой поток выдерживает задержку реакции (`reaction_ms` + случайная добавка) и стреляет **не чаще одного раза за такт**, поэтому реальный интервал между выстрелами не короче такта. |
| `0` | Быстрое моделирование без реального времени. Координатор не начинает следующий такт, пока оба огневых потока не отработали текущий (каждый стреляет ровно один раз, если может). Задержки реакции не применяются. Число выстрелов детерминировано; порядок выстрелов A и B внутри такта определяет планировщик. |

Экономическое ограничение: сторона прекращает огонь, когда **следующий** выстрел
вывел бы израсходованную стоимость за предел бюджета (при бюджете 5 и цене 3
возможен один выстрел).

## Стратегии выбора координат

| Стратегия  | Описание                                             |
|------------|------------------------------------------------------|
| `random`   | Равномерный случайный выбор координат                |
| `center`   | Приближённое смещение к центру (треугольное)         |
| `sector`   | Циклический последовательный обход клеток по индексам |

Стратегия **не использует** информацию о расположении целей —
противник их не знает.

## Тяжёлый удар (площадной)

Раз в `area_every` тактов (если `area_every > 0`, есть тяжёлые снаряды
и бюджет позволяет) сторона тратит один тяжёлый снаряд и накрывает
квадрат `(2R+1)×(2R+1)` вокруг выбранной точки. Все живые цели в этой
области уничтожаются одновременно. Каждая цель при этом учитывается
**один раз**.

Если `area_every=0`, тяжёлые залпы не применяются, и такие снаряды
не считаются боеспособным запасом.

## Лог-файл

Имя лог-файла задаётся параметром `log` в конфиге или по умолчанию
`duel.log`. В лог попадают:

- все события выстрелов и залпов;
- попадания, промахи, уничтожение целей;
- пополнение боезапаса;
- срабатывания условий прекращения огня;
- итоговая статистика обеих сторон;
- вердикт;
- финальное состояние обеих территорий.

Цветовые ANSI-последовательности **вырезаются** при записи в файл —
лог остаётся чистым текстом.

## Автотесты

Каждый тест проверяет не только код возврата, но и **содержимое** вывода. Для любого прогона
дополнительно проверяются инварианты ТЗ по журналу: после «ПРЕКРАЩАЕТ ОГОНЬ» сторона не стреляет,
остатки, число и стоимость целей не отрицательны, число выстрелов в журнале равно статистике,
попадания + промахи = выстрелы.

Сценарные проверки: ровно один выстрел в `case_tiny`; пополнение даёт 10 выстрелов и 10 пополнений
в `case_replenish`; в `case_destroyed_cell` есть повторное попадание в разрушенную клетку, потери
ровно 12; расход свыше `INT_MAX` в `case_overflow`; радиус 0 и цена 0 без ложного «бюджет исчерпан»
в `case_area_zero`; типы целей в `case_types`; отклонение стоимости свыше 10⁹ (`bad_cost`);
закрытый канал вывода (`sigpipe`); интерактивный ввод со всеми параметрами и обработка EOF;
воспроизводимость одного seed. Тест `thread_structure` проверяет два потока сторон, два огневых
потока, координатор и разные `pthread` ID.

На текущей папке проекта в Ubuntu обычный набор прошёл `24/24`, ASan/UBSan — `24/24` без диагностик. В WSL2 прямой запуск TSan первоначально завершался до старта программы с `FATAL: ThreadSanitizer: unexpected memory mapping`; после запуска тестовой обёртки через `setarch -R` TSan прошёл `24/24` без диагностик. В контрольной серии дополнительно прошли 30 быстрых запусков (10 для каждого из трёх граничных сценариев) и 20 запусков реального времени (по 5 для четырёх сценариев). Ранее также выполнялась расширенная серия из 320 быстрых прогонов. Чувствительность набора проверялась на версии до исправлений: она не проходит 11 из 24 тестов.

```bash
bash ./scripts/run_tests.sh
```

Скрипт запускает бинарник на всех конфигах из `scripts/cases/`,
плюс проверяет сигналы, ошибки конфигурации, интерактивный режим. Результаты
сохраняются в `tests/` (лог-файлы сценариев тоже). Путь к бинарнику можно задать
переменной `BIN` (например, для сборки с санитайзерами).

## Инварианты

Программа гарантирует:

- **Один выстрел — не более одного снаряда.**
- **Цель учитывается уничтоженной только один раз.**
- **Стоимость и число целей не становятся отрицательными.**
  Стоимость одной цели проверяется на диапазон 0..10⁹ до записи в клетку,
  суммарные стоимости (`initial_cost`, `alive_cost`, `lost_cost`) хранятся в
  `int64_t` — переполнение невозможно.
- **Сторона меняет территорию противника только выстрелом.** Свой флаг
  `active` сторона меняет сама; общую проверку завершения делает координатор.
- **После срабатывания условия завершения сторона не стреляет:** проверка
  и выстрел выполняются под одной блокировкой, возобновления огня нет.

## Архитектура (модули)

| Модуль       | Роль                                              |
|--------------|---------------------------------------------------|
| `main`       | Координатор: разбор аргументов, главный цикл     |
| `artillery`  | Огневое подразделение                            |
| `side`       | Государство: территория + подразделение          |
| `grid`       | Территория: клетки, цели                         |
| `config`     | Парсер параметров, дефолты, интерактив           |
| `log`        | Логирование через `write()`, вырезание ANSI      |
| `io`         | Построчное чтение через `read()`                 |
| `signals`    | Обработчики SIGINT/SIGTERM                       |
| `colors`     | ANSI-цвета с автоотключением                     |

## Использованные интерфейсы POSIX и функции libc

- `open`, `read`, `write`, `close` — работа с файлами, интерактивным вводом и логом;
- `nanosleep`, `clock_gettime` — задержки и монотонные дедлайны;
- `sigaction` — обработка `SIGINT`/`SIGTERM` и игнорирование `SIGPIPE`;
- `pthread_create`, `pthread_join`, `pthread_mutex_lock`/`pthread_mutex_unlock`, `pthread_sigmask` — потоки и синхронизация;
- `sem_init`, `sem_wait`, `sem_timedwait`, `sem_post` — POSIX-семафоры;
- `isatty` — определение интерактивного терминала.

Основной игровой ввод-вывод и логирование используют файловые дескрипторы. Несколько
диагностических сообщений командной строки в `main.c` выводятся через `fprintf(stderr, ...)`.
